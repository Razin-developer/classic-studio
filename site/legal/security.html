Security policy

Security practices and reporting guidance for the local app and future hosted services.

Last updated: October 14, 2026

Current product boundary

The current editor is a local desktop application. Its protection depends on the operating system account and filesystem permissions. Treat project files as sensitive if they include confidential content.

Release verification

Public releases should provide checksums and provenance. Verify a downloaded artifact before running it, and obtain it only from the configured release location.

Reporting a vulnerability

Before launch, the project operator must publish a monitored security contact and disclosure policy. Do not post exploitable details in public issues until a maintainer confirms a safe disclosure route.

Hosted service commitments

Any future collaboration, authentication, or AI service must implement transport security, authentication controls, authorization checks, input validation, rate limits, auditability, secret rotation, dependency updates, and incident response procedures before public availability.

Scope

Security issues in the project source, packaged desktop builds, official web properties, and official hosted services are in scope once a reporting contact is published.
